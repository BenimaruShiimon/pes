poe_watchdog
============

`poe_watchdog` — демон для контроля состояния PoE-порта по физическому интерфейсу и автоматического power-cycle при отсутствии признаков жизни.

Назначение
----------
- Контролировать состояние физического интерфейса `monitor_iface`.
- Следить за наличием carrier и/или трафика на выбранном интерфейсе.
- При нарушении условий автоматически выполнять `off`/`on` на PoE-порту.
- После восстановления питания возвращать требуемый режим PoE (`AUTO`, `SEMIAUTO`, `OFF` и т.п.).
- Поддерживать работу как через локальный PoE-демон `poed` (Unix socket), так и через sysfs-пути на платформах с прямым управлением PoE.
- Работать без изменения основного switch-app-кода: логика вынесена в сам пакет watchdog.

Что именно делает watchdog
---------------------------
Демон читает конфигурацию из `/etc/poe_watchdog.conf`, создаёт отдельный мониторинг для каждой строки и проверяет состояние PoE-порта по физическим признакам:

1. отсутствие `carrier` на `monitor_iface` в течение `link_timeout_sec`;
2. отсутствие трафика на выбранном интерфейсе (`monitor_iface`) в течение `idle_threshold` секунд.

Если выполняется одно из условий, то watchdog принимает решение о сбросе порта:
- `watch_scope=link` — только отсутствие carrier.
- `watch_scope=os` — только отсутствие трафика.
- `watch_scope=both` — любая проблема из двух критериев приводит к сбросу.

После срабатывания:
- порт переводится в `off`;
- выполняется задержка `cycle_pause_sec`;
- порт переводится в `on`;
- восстанавливается режим `mode` (например `SEMIAUTO`), если он задан;
- дальше начинается новый период проверки после `cooldown_sec`.

Файловая структура
-------------------
- `poe_watchdog.c` — главный демон.
- `poe_ctl.sh` — обертка над платформенным управлением PoE.
- `poe_sock_ctl.c` — низкоуровневый helper для управления через Unix socket и sysfs.
- `poe_watchdog.conf` — пример конфигурации.
- `README.md` — описание функциональности и пользовательский сценарий тестирования.
- `USERGUIDE.md` — эксплуатационный гайд для тестировщика на производстве.
- `S99poe_watchdog` — init-скрипт для BusyBox init.
- `Config.in` — вход в Buildroot menu.
- `poe_watchdog.mk` — Buildroot пакет.

Как это работает
----------------
1. Демон читает `/etc/poe_watchdog.conf`.
2. Для каждого `port` создаётся отдельный объект мониторинга.
3. Демон циклически проверяет:
   - состояние `carrier` на `monitor_iface`;
   - суммарный трафик `rx_packets + tx_packets` на `monitor_iface`;
   - предустановленный `watch_scope`.
4. При превышении `fail_threshold` или отсутствии признаков жизни watchdog запускает `power_cycle_port()`.
5. Power-cycle выполняется как `off -> on`, после чего восстанавливается `mode`.
6. `cooldown_sec` не позволяет запустить следующий сброс слишком быстро.
7. По сигналу `SIGHUP` демон перечитывает конфиг без перезапуска.

Конфигурация
------------
Формат `/etc/poe_watchdog.conf`:

```
<port> <interval_sec> <fail_threshold> <cooldown_sec> <cycle_pause_sec> <monitor_iface> <idle_threshold> [mode [watch_scope [link_timeout_sec]]]
```

Параметры:
- `port` — идентификатор порта, понятный `poe_ctl.sh`.
- `interval_sec` — период проверки интерфейса.
- `fail_threshold` — число повторов до сброса по физическому событию.
- `cooldown_sec` — пауза после восстановления питания до следующей проверки.
- `cycle_pause_sec` — задержка между `off` и `on` внутри power-cycle.
- `monitor_iface` — обязательный физический интерфейс, по которому контролируется carrier и трафик.
- `idle_threshold` — время простоя трафика в секундах до срабатывания.
- `mode` — режим PoE после восстановления, например `AUTO`, `SEMIAUTO`, `OFF`.
- `watch_scope` — `os`, `link` или `both`.
- `link_timeout_sec` — время без carrier на `monitor_iface` до power-cycle, используется при `watch_scope=link` или `both`.

Примеры конфигурации:

```
G01    5    3    60    5    eth0    30    SEMIAUTO    link    20
G02    5    3    60    5    eth0    30    SEMIAUTO    link    20
G05   10    3   120    5    eth0    60    SEMIAUTO    both    30
```

Проверять только трафик ОСИ:

```
G01    5    3    60    5    eth0    30    SEMIAUTO    os
```

Проверять carrier и поток одновременно:

```
G01    5    3    60    5    eth0    30    SEMIAUTO    both    20
```

Поведение в критических ситуациях
----------------------------------
- Если на физическом интерфейсе нет `carrier`, watchdog сработает при `watch_scope=link` или `both`.
- Если на интерфейсе нет трафика дольше `idle_threshold`, watchdog сработает при `watch_scope=os` или `both`.
- Если `monitor_iface` не задан, watchdog не имеет физической метрики для контроля и не запускается.
- Если `mode` не задан, демон сохраняет текущий режим как есть, если платформа поддерживает восстановление по `poed`/sysfs.

Адаптация PoE управления
------------------------
`poe_ctl.sh` и `poe_sock_ctl.c` должны быть настроены под реальную платформу.
Поддерживаются варианты:
- вызов локального PoE-демона `poed` через Unix socket `/var/run/poed.sock`;
- запись в sysfs-пути вида `/sys/poe*/...`;
- чтение и запись через `port_info`/`port_power_on`/`port_power_off`;
- варианты записи как числовым индексом порта, так и именем, например `G24`.

Приоритет работы:
1. Socket/демон `poed`.
2. Sysfs-пути `/sys/poe*`.
3. Платформенные CLI-команды.

Если все способы недоступны, watchdog пишет ошибку и делает запись в syslog.

Логирование
-----------
Демон пишет подробные записи в syslog. Логи делятся на уровни:
- `LOG_DEBUG` — диагностика пингов, таймеров, счётчиков трафика и парсинга конфигов.
- `LOG_INFO` — запуск, восстановление, срабатывание watchdog.
- `LOG_WARNING` — аномалии, повторное восстановление или частичные ошибки.
- `LOG_ERR` — не удалось выполнить `off`/`on`, не найден контроллер PoE, проблемы с сокетом или sysfs.

Для продакшн-установки рекомендуется оставлять логирование на уровне `LOG_INFO` и выше, чтобы избежать перегруза журналов.

Быстрая проверка на устройстве
------------------------------
Проверить доступность sysfs и порта:

```
ls -l /sys/poe*
cat /sys/poe0/port_info
```

Проверить ручное управление через sysfs:

```
# числовой индекс
# пример: 0-based index
echo 0 > /sys/poe0/port_power_off
echo 0 > /sys/poe0/port_power_on

# имя порта
# пример: G24
echo G24 > /sys/poe0/port_power_off
echo G24 > /sys/poe0/port_power_on
```

Проверить через адаптер:

```
/usr/sbin/poe_ctl.sh G24 off
/usr/sbin/poe_ctl.sh G24 on
/usr/sbin/poe_ctl.sh G24 cycle
```

Сборка и интеграция
-------------------
1. Проверить, что Buildroot собран с `BR2_EXTERNAL=./external`.
2. Включить пакет `poe_watchdog` в `menuconfig`.
3. Собрать образ.
4. Убедиться, что binary и init-скрипт попадут в конечный образ.

Запуск на целевом устройстве
----------------------------
- Демон: `/usr/sbin/poe_watchdog`
- Обертка: `/usr/sbin/poe_ctl.sh`
- Конфиг: `/etc/poe_watchdog.conf`
- Init: `/etc/init.d/S99poe_watchdog`

Основные команды:

```
service S99poe_watchdog start
service S99poe_watchdog stop
service S99poe_watchdog restart
service S99poe_watchdog reload
```

Добавление/обновление записи через CLI:

```
/usr/sbin/poe_watchdog -A 'G01 5 3 60 5 eth0 30 SEMIAUTO link 20'
/usr/sbin/poe_watchdog -c /etc/poe_watchdog.conf -A 'G05 10 3 120 5 eth0 60 SEMIAUTO both 30'
```

Эта команда парсит строку в формате без адреса, обновляет существующий target по `port` и добавляет новый, если записи ещё нет.

Рекомендуемые эксплуатационные ограничения
------------------------------------------
- Перед использованием обязательно проверить, что порт реально поддерживает PoE и `poe_ctl.sh` корректно находит нужный port-id.
- Не использовать очень маленький `fail_threshold` на линках с кратковременными пинг-потерями.
- Учитывать, что на промышленных сетях возможна временная неактивность devices при запланированном обслуживании.
- Для VLAN/bridge-порта деликатно подбирать `monitor_iface`, чтобы не ловить ложные срабатывания.
- Для тестирования в production следует сначала включить watchdog в mode `dry-run`/лог-режим, если он будет добавлен в платформе.

Важно
-----
- Перед эксплуатацией обязательно сверить значения порта и режима PoE с реальной платформой.
- Не использовать `watch_scope=both` там, где физический интерфейс может быть тихим по природе работы.
- Если PoE-демон `poed` не доступен, надо проверить sysfs-пути и наличие прав на запись.
- Полезно сохранить копию конфигурации до включения watchdog в продакшн.
